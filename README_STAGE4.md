# Achievement Manager v0.8 — Stage 4（開発版）

## 変更点
- 実績管理画面を整理。実績名・テンプレート・達成回数・★ランク、特殊条件（Beta）、新規追加／変更を保存／クリア。
- 未保存の編集は別実績選択・新規作成・クリア・タブ移動・ウィンドウ終了時に確認。保存前にDBへ書き込まない。
- カスタム実績を実績一覧・個人実績カードに反映。新規実績は未解除・進捗0として表示。
- コメント、Twitchエモート、キーワード、チャネポ（イベントが受信された場合）の解除判定、AND/OR条件を追加。
- v0.7の固定実績と履歴を保持。初回起動時に従来DBを `achievements.before_stage4.db` へバックアップ。
- Stage 3 の `achievements_v08_preview.db` が存在すれば、保存済み定義を既存DBへ取り込みます。

## 更新手順
1. **アプリを終了**。既存の `%LOCALAPPDATA%\AchievementManager\achievements.db` を別の場所にもバックアップ。
2. `develop-v0.8` ブランチに、このZIPの `main.py`、`achievement_editor.py`、`achievement_core/` を配置。その他の既存ファイルはそのまま残します。
3. 既存の `requirements.txt` で依存関係を入れ、Windowsで `python main.py` を実行。
4. 新規実績を作成し、実績一覧・個人実績カードで確認。テストイベント／実際のTwitchイベントで解除を確認。

## 現時点の制約・注意
- **こちらの実行環境にはPyQt5がなく、Windows画面の実機操作テストは未実施**。Python構文検証・DB/判定ロジックの検証を実施しています。
- 旧TKG自動連携と固定実績は残存。一般公開向けの任意TKG接続化は未対応。
- Twitchチャネポイベントは従来の接続実装で自動受信しません。イベント入力が渡った場合のみカウントします。
- 既存の視聴者履歴を保持するため、解除済み実績は条件変更後も解除済みとして保持します。未解除の進捗はイベントカウンターから再計算されます。
- キーワード条件は**Stage 4で受信したチャット**からカウントします。過去ログは再集計しません。
- 新規実績作成前から蓄積されたコメント数等は共通カウンターから参照されます。条件を既に満たす場合、次のイベント時に解除されることがあります。
- Stage 4では高度な時系列条件・N個中M個達成・カスタムスクリプトには対応していません。
